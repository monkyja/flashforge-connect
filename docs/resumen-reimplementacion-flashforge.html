Estado en una frase

Se conoce parte del contrato nativo, pero aún no lo suficiente para reemplazar el SDK completo. La dirección acordada es reimplementar en Python dentro del plugin OrcaSlicer, usando el runtime que acompaña a Orca en Windows y Flatpak, sin instalar dependencias aparte.

La reimplementación no está hecha. El backend actual todavía usa libFlashNetwork.so y FLASHNETWORK9.DAT; además, bridge.py lanza /usr/bin/python3.

Hallazgos de ingeniería inversa

Hecho

Versión y símbolos

La versión 3.4.0 se construye en fnet_getVersion, VA 0x6abf0. La biblioteca exporta 119 funciones C y la cabecera declara exactamente esas 119.

Hecho

Escrituras MQTT

fnet_connectionSend (0xa0b50) usa MqttConn::send (0x10ded0) y el serializador writeData2Str (0x10df35).

Hecho

sendMulti

La implementación requiere dataCnt == 1 o dataCnt == topicCnt. El comentario de cabecera permite más combinaciones. Hay que revisar failedCnt, aunque el retorno sea cero.

Inferencia

Evento de descarga

El parser compara dos veces job_download para tipos 12 y 13. La rama de tipo 13 parece inalcanzable; falta confirmar con un mensaje sintético.

Controles encontrados

Los serializadores contienen comandos para temperatura, luz, ventiladores, movimiento, homing, materiales, trabajo, cámara y configuración de materiales. Ejemplos documentados en cabecera: trabajo pause/continue/cancel; cámara open/close. Esto describe formato, no valida soporte físico en Creator 5 Pro.

Consultas HTTP localizadas

FunciónVARuta observada
fnet_getWanDevGcodeList0x7f4b0/api/v2/external/truck/device/local_files?id=%s
fnet_getWanDevTimeLapseVideoList0x802a0/api/v2/external/truck/device/delay_video/list?id=%s&currentPage=1&pageSize=%d

Las rutas no revelan por sí solas host, autenticación completa ni un contrato estable. No se llamaron.

DAT y dominios observados

Hecho

Formato

Encabezado FNETDAT-1.2.0. Se reconstruyeron 314 bytes de carga al verificar 1.783 enteros de relleno MT19937. El lector de la biblioteca llama a AES-256-OFB.

Pendiente

Significado

El esquema completo y la relación de cada servicio con operaciones concretas aún no están trazados. No se guardó la configuración descifrada ni se exponen claves.

Una comprobación estática posterior descifró la carga solo en memoria y filtró hostnames:

api.fdmcloud.flashforge.comapi.voxelshare.comauth.voxelshare.comreport.voxelshare.comdesktop.voxelshare.com:8083/mqtt
Precaución: son valores de configuración observados. No prueban qué función usa cada host, si siguen activos o a qué host pertenece el fragmento MQTT. auth.voxelshare.com faltó en la primera lista y queda corregido aquí.

El usuario quiere excluir la plataforma Voxelshare. api.fdmcloud.flashforge.com es candidato a servicio de máquina, pero aún debe confirmarse siguiendo referencias desde las funciones del SDK.

ABI, memoria y materiales

  • La documentación registra layouts y funciones de liberación para estructuras principales; las mediciones corresponden al host x86-64.
  • El consumidor usa topic recibido y QoS 1; no inventar topics desde IDs.
  • La estructura real de evento contiene topic, aunque un comentario antiguo dice devId.
  • toolId y slotId son campos separados. No asumir equivalencia entre herramienta G-code y ranura.
  • La ruta de envío del informe distingue subida, creación del trabajo y despacho MQTT. Despachar no prueba que la impresora haya empezado.

El informe completo contiene símbolos, VA, offsets, claves serializadas, tamaños, offsets de campos y comandos reproducibles.

Qué falta para reemplazar el SDK

Cuenta

Rutas y cuerpos de login/renovación; respuesta y pasos exactos requeridos para autorizar operaciones de máquina.

Servicios

Asignar hosts a operaciones y confirmar si se puede excluir Voxelshare sin romper acceso a máquina.

MQTT

Broker, puerto/TLS, autenticación, topics, suscripciones, reconexión y contratos de eventos.

Creator 5 Pro

Capacidades, estados, ranuras/materiales y confirmaciones físicas observables.

No se incorporarán secretos de aplicación del fabricante ni se eludirá autenticación. Si el servicio exige credenciales no disponibles para clientes independientes, se registrará como bloqueo.

Python incluido en OrcaSlicer

OrcaSlicer fija plugins .py/.whl y empaqueta Python según el formato. Para el objetivo del proyecto:

PaqueteRuntime señalado por el código fijado
Instalador Windows<directorio de OrcaSlicer>\python\python.exe
Flatpak 2.5.1CPython 3.12.13 en /app/libpython
AppImageRuntime en el árbol empaquetado
FHS simplePuede no incluir runtime
Objetivo acordado: plugin Python que use el Python incluido por OrcaSlicer en Windows y Flatpak. El usuario no instala Python ni paquetes aparte.

El código actual no cumple aún este requisito: bridge.py usa /usr/bin/python3. Hay que localizar el Python de Orca sin fallback silencioso al Python del sistema. Las dependencias serán estándar o viajarán en el wheel con licencia y procedencia documentadas.

2 · TransporteModelos neutrales y HTTP/MQTT sustituibles, sin SDK ni DAT.
3 · LecturasAutorización necesaria, lista y estado; todo con dobles locales.
4 · EventosAñadir MQTT, cámara y controles solo cuando estén demostrados.
5 · TrabajosSubida, creación y despacho como fases distintas.
6 · MigraciónUsar Python incluido; retirar SDK/DAT y revisar paquete.
7 · ValidaciónWindows/Flatpak; login/lectura primero, acciones físicas nunca automáticas.
GateNo implementar contratos con host, ruta o campos supuestos.

Legalidad y nivel de validación

La conversación revisó que la Directiva europea 2009/24/CE permite, bajo condiciones, descompilar lo imprescindible para interoperabilidad de un programa independiente. No es permiso general ni determina por sí sola la legalidad de este caso. El EULA publicado restringe análisis y redistribución; su interacción con la excepción exige asesoramiento jurídico. El plan no incluye redistribuir los binarios originales.
